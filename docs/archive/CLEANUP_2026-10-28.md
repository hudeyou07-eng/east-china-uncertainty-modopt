# 中间产物清理台账（2026-10-28）

## 为什么清理、清理到什么程度

`outputs/` 下有 199 个目录、33 MB，但**被文档结论引用的只有 36 个**。其余是：
被取代的旧批次、并行分片、重复 smoke、标 `INCOMPLETE`/`DRY_RUN`/`FAILED` 的失败尝试、纯空目录。

清理的硬约束（用户要求）：**不得破坏仓库内逻辑内容的完整性、严谨性与准确性**。
据此设三条规则：

1. **只删「有明确替代者」或「从未产出结果」的目录**。任何被 `EXPERIMENT_TRACKER.md` /
   `CHANGELOG` / `PANEL_LEDGER` / `DECISIONS` 当作**当前证据**引用的目录，一律保留。
2. **删除前先验证等价性**，不是凭标记删。分片目录先与合并目录做逐元素比对，
   重复 run 先与主批次比对，确认 `max|diff| = 0` 才删（见下「验证记录」）。
3. **删除后复核引用可解析性**，把「正文提到但目录已删」的每一处都登记在下方「失效引用登记」，
   说明它引用的是历史过程还是当前证据。

清理规模：**163 个目录 / 1630 个文件 / 17.9 MB**（`outputs` 33 MB → 15 MB，目录 199 → 36）。
逐条明细见同目录 `outputs/_cleanup_deleted.csv`（`group, dir, files, bytes`）。

### 风险提示：两处 smoke 数值不再可现场核验

`TRACKER` L480 与 L578 引用了两个已删 smoke 目录里的**具体数字**。这两个数字当前
**没有留在磁盘上**，无法逐元素复核：
- L480：`R200_203_b2_smoke_20261027_151138` 与 R307b 的数值吻合（用于交叉验证 gate 结论）；
- L578：`R200_203_b2_smoke_20261026_180400` 的 smoke 实测表。

**这不算破坏严谨性**（它们本来就是 smoke，`evidence_status` 非 `formal`），但应知道：
引用这两个数字时只能引 `TRACKER` 的记载，**不能声称可现场复算**。
若需现场复核，用 `scripts/run_b2.py --profile smoke` 重跑可得同量级结果（S=200、2 repeats）。
